# Агрегация результатов и обратная связь

Агрегация объединяет результаты нескольких проверок в общий результат проверки решения. Метод агрегации определяет, какие проверки нужно рассмотреть вместе, когда можно продолжить решение и какие сообщения об ошибках или подсказки следует показать обучаемому.

На этой странице рассматривается связь методов агрегации с обратной связью. Описание самих узлов и правил вычисления результатов см. в [[./Узлы.md#агрегация-и-узлы-агрегации|«Узлах»]].

## Основные понятия

**Ветвь мысли** представляет логически завершённую часть алгоритма, отвечающую на отдельный вопрос. При выполнении ветви решение проходит путь от её начального узла до узла, определяющего результат. Узел агрегации объединяет результаты вложенных ветвей; в цикле такими результатами являются результаты отдельных итераций.

Три возможных результата ветви мысли:

- `true` — ответ корректен с точки зрения проверок данной ветви (`BranchResult.CORRECT`).
- `false` — в ответе есть конкретная ошибка (`BranchResult.ERROR`).
- `null` — корректность ответа не установлена либо ответ настолько неправильный, что невозможно установить конкретную ошибку (`BranchResult.NULL`).

Для описания обратной связи неопределённые результаты можно различать по тому, к каким результатам ведут другие пути из того же узла:

- `null(t)` — остальные пути ведут только к результатам `null` и `true`.
- `null(f)` — остальные пути ведут только к результатам `null` и `false`.

Эти обозначения уточняют смысл неопределённости при выборе сообщения; в модели оба случая соответствуют `BranchResult.NULL`.

Агрегация имеет две формы: **по ветвям** и **в цикле**.

**Ситуация** — текущее состояние решения задачи, то есть условие и частичное решение.

## Последовательность, SEQ

Последовательность применяется, когда проверки нужно выполнять в заданном порядке до первого определённого результата. Если очередная проверка дала `true` или `false`, последующие проверки не выполняются. Если все проверки дали `null`, результат последовательности также равен `null`.

**Обратная связь:** при ошибке выводится сообщение, связанное с узлом результата `false`; при подсказке — сообщение, связанное с узлом результата `true`.

**Визуальное представление:** последовательность по ветвям не имеет отдельного узла и отображается соединением узлов по переходам с результатом `null`. Цикл отображается шестигранником с надписью `SEQ`.

В модели последовательному циклу соответствует `WhileCycleNode`. Его тело выполняется, пока выполняется условие цикла и очередная итерация возвращает `null`. Состояние, от которого зависит условие, изменяется действиями внутри тела цикла. Результат `true` или `false` завершает цикл; завершение по условию даёт результат `null`.

**Продолжение решения:** переход по `null` определяет следующий шаг, если последовательность не дала определённого результата.

## Взаимоисключающие проверки, MUTEX

Взаимоисключающие проверки применяются, когда в любой ситуации не более одной ветви может дать определённый результат. Поэтому порядок выполнения ветвей не имеет значения. Каждая ветвь может содержать несколько узлов с разными результатами, но две ветви не могут одновременно дать результаты, отличные от `null`.

Результатом агрегации становится единственный определённый результат. Если все ветви дали `null`, результат агрегации также равен `null`.

**Обратная связь:** при ошибке выводится сообщение, связанное с узлом результата `false`; при подсказке — сообщение, связанное с узлом результата `true` применимой ветви.

**Визуальное представление:** шестигранник с надписью `MUTEX`. Дополнительная надпись может пояснять смысл группы проверок.

**Продолжение решения:** переход по `null` позволяет перейти к следующим проверкам, если ни одна из ветвей не дала определённого результата. Обязательных переходов для `MUTEX` нет.

## Независимые проверки, SIM:AND и SIM:OR

Независимые проверки применяются, когда для оценки решения необходимо рассмотреть несколько факторов независимо друг от друга и отобразить их результаты. Способ объединения результатов определяется логической связью между проверками.

### Независимые проверки по логическому И, SIM:AND

Основная ветвь корректна, только если корректны все вложенные ветви. Результат вычисляется как логическое И с неопределенностью:

1. `null`, если хотя бы одна ветвь дала `null` (или ветвей нет).
2. `false`, если хотя бы одна ветвь дала `false`.
3. `true` иначе, то есть если все ветви дали `true`.

> [!note]
> До `its_Reasoner` `3.0.0-rc.7` `null` во вложенных ветвях игнорировался: сочетание `true` и `null` давало `true`, а `false` и `null` - `false`. Если ветви SIM:AND могут дать `null`, результат узла после обновления может измениться.

**При ошибке:** выводятся независимые сообщения для каждого узла результата `false`.

**При подсказке:** выводится единое сообщение, состоящее из сообщений узлов результата `true`, связанных «а также» или подобными связками. Такая подсказка объединяет факторы, которые нужно учесть вместе.

**Продолжение решения:** из узла должен быть переход по `true`.

### Независимые проверки по логическому ИЛИ, SIM:OR

Для корректности основной ветви достаточно корректности хотя бы одной вложенной ветви. Результат вычисляется так:

1. `null`, если все ветви дали `null`.
2. `true`, если хотя бы одна ветвь дала `true`.
3. `false` иначе.

**При ошибке** обратную связь можно организовать двумя способами:

- Вывести единое сообщение, состоящее из сообщений узлов результата `false`, связанных «а также» или подобными связками.
- Задать уточняющий вопрос «Какую из ветвей вы считали истинной?» и вывести сообщение по выбранной ветви. Если выбран вариант «Ни одну», объяснить, что для истинности общего результата достаточно истинности хотя бы одной ветви.

**При подсказке:** выводятся отдельные сообщения для ветвей, давших `true`. Каждая из них указывает на фактор, достаточный для корректности общего результата.

**Продолжение решения:** из узла должны быть переходы по `false` и `null`, поскольку эти результаты требуют рассмотрения всех ветвей вместе.

Оба вида независимых проверок отображаются шестигранником с надписью `SIM:AND` или `SIM:OR`.

## Гипотезы, HYP

Гипотезы применяются, когда ответ обучаемого не позволяет однозначно определить ход его рассуждений. Каждая ветвь соответствует предположению о том, как он мог прийти к своему ответу.

При агрегации `true` имеет приоритет над `false`, а `false` — над `null`.

**При ошибке:** задаётся уточняющий вопрос по всем гипотезам, давшим результат, отличный от `null`. Обратная связь определяется выбранной гипотезой: обучаемому показывается результат проверки корректности или сообщение о конкретной ошибке.

Если среди гипотез есть как корректные, так и ошибочные рассуждения, уточняющий вопрос позволяет выяснить, какими рассуждениями руководствовался обучаемый. Общий результат агрегации при этом равен `true`.

Если все ветви дали `null`, для обратной связи используется сообщение, связанное с `null(t)`: оно относится к ветви, которая дала бы правильное решение в текущей ситуации при другом ответе обучаемого.

**При подсказке:** выводится сообщение, связанное с узлом результата `true` в данной ситуации.

**Визуальное представление:** шестигранник с надписью `HYP`.

**Продолжение решения:** из узла должен быть переход по `null`, чтобы обработать ситуацию, в которой ни одна гипотеза не дала определённого результата.
