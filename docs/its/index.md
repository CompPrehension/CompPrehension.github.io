# Описание CompPrehension

**CompPrehension** — это интеллектуальная обучающая система (Intelligent Tutoring System, ITS). (Для обозначения подсистемы, связанной непосредственно с обучением, иногда используется термин «тренажёр».)  
CompPrehension — это развивающийся проект, созданный силами научной группы каф. ПОАС ВолгГТУ.

Идея, лежащая в основе проекта, состоит в том, чтобы _моделировать процесс понимания_ обучающимся изучаемой темы (**предметной области**).
Созданные в рамках проекта модели понимания позволяют системе без участия преподавателя давать обучающимся **обратную связь**, осмысленно отвечающую на сделанные ошибки.

## Окружение для разработки

- Java (JDK 21 (рекомендуется) или 25)
- Система сборки Maven
- MySQL 8.0+

**Рекомендуемые IDE:** IntelliJ IDEA

Фреймворки и библиотеки:

- используются в основном коде проекта: Spring Boot, Hibernate/Persistence, lombok, etc.
- вспомогательные проекты экосистемы: [Meaning Tree](/docs/meaning_tree/), [Thought Process Tree Model](/docs/decision_tree/)

_Рисунок_. Общая «плагинная» архитектура: **ядро**, его 4 ключевых компонента и их _возможные_ реализации во внешнем контуре (в качестве плагинов)

В любой расширяемой системе должно быть стабильное «ядро», предоставляющее точки расширения для подключения плагинов. В нашем случае ядро включает в себя четыре ключевые подсистемы — это **Домен**, **Стратегия**, **Фронтенд** и **Бэкенд**.

### Domain

Каждая предметная область, или **дом_е_н** (**Domain**), покрывает свою тему, имеет свой формат и состав учебных задач. К примеру, исторически первые два домена, появившиеся в нашей системе, касались:

- порядка вычисления выражения в программировании (охватывает такие понятия, как приоритет и ассоциативность операций, скобки, «ленивое» вычисление),
- порядка выполнения алгоритмических структур (учит правильно понимать вложенность и поведение типовых структур кода — if/else, while/do-while, for).

Сейчас в разработке ещё несколько доменов. Некоторые из них касаются не программирования, а грамматики английского языка.  
Диапазон тем, для которых можно сделать новый домен, не ограничен. Желательной является высокая степень формализации предметной области, чтобы определять неправильность ответов с высокой степенью уверенности (но лучше с абсолютной ☺).

### Strategy

Для обеспечения возможности продолжительных тренировок (например, при подготовке дома) тренажёр должен уметь подбирать серии (цепочки) заданий, управляя параметрами каждого следующего задания (например, понемногу повышать сложность). Такие цепочки заданий мы называем **упражнениями**.  
За формирование цепочки заданий в рамках упражнения отвечает плагин «**Стратегия**» (**Strategy**). Стратегия руководствуется в первую очередь настройками упражнения, которые задаются учителем. Также могут быть использованы все доступные знания о обучающемся, например, о его предыдущем взаимодействии с системой.

### Backend

Доменам со сложной внутренней логикой требуются специализированные средства для того, чтобы решать задачи. Да, домен должен сам уметь решать задачи, чтобы вычислять текущее состояние решения задачи и подсказывать следующие правильные шаги либо оценивать очередной частичный ответ.

Нужен отдельный решатель, или машина вывода, или формальный рассуждатель (**reasoner**). В общем, нечто, что невидимо извне, но выполняет сложную работу,  из-за чего система в целом кажется «умной». Мы назвали его **Backend**.

Актуальные варианты бэкенда:

- Apache **Jena** — решатель общего назначения на продукционных правилах (ещё работает, но морально устаревает),
- its_Reasoner для работы с (Thought Process Tree/Decison Tree, DT) — перспективная технология для обработки деревьев решений (моделей мышления собственного формата) (внутренняя разработка).

### Frontend

Каждому домену нужно отображать свои задачи в пользовательском интерфейсе (UI), чтобы каким-либо образом взаимодействовать с обучающимся.
Это не обязательно должен быть экран монитора, мышка и клавиатура. Теоретически, ничто не мешает учиться в интерфейсе чат-бота на смартфоне.  
Поэтому общее название способа взаимодействия с пользователем — **Frontend**. Под этим понятием скрываются любые виды UI, необходимые обучающимся для  взаимодействие с тренажёром.

Новые плагины типа Frontend определяют способ доступа к пользователю и _физически_ поддерживаемые _функциональные возможности_ пользователя в этом варианте взаимодействия. Например, в чат-боте нельзя поместить интерактивный HTML, по которому можно кликать мышкой, но можно только давать краткие ответы, выбирая из предложенных вариантов или вводя короткие текстовые фрагменты.

### Question Bank

Чтобы подбирать индивидуальные задания в рамках упражнения, у системы должен быть выбор таких заданий. Они хранятся в **банке вопросов** и могут быть получены оттуда по требованию.
Для целей поиска каждый вопрос размечен уймой разных показателей (**метаданных**):

- ссылка на домен, для которого он предназначен
- обобщенный уровень сложности,
- количество шагов решения,
- фигурирующие и участвующие в решении понятия предметной области (концепты, концепты по "трассе"),
- виды потенциальных ошибок (которые возможно совершить в процессе решения) — "violations" / "negative laws",
- теги,
- … (и ещё кое-что).

Банк вопросов хранит все возможные и перспективные виды вопросов и на настоящий момент не предполагает существования альтернативных реализаций банка вопросов. «Под капотом» банк «завязан» на возможности MySQL и её SQL-диалекта.

### Question Generator («внешняя» подсистема)

Активно разрабатываемая область проекта.  
Генератор вопросов позволяет наполнять банк вопросов параллельно деятельности самого тренажёра, но с учётом его потребностей в определённых видах вопросов.  

Генератор вопросов обычно для каждого домена свой, отдельный. Каждый генератор знает, какие типы вопросов и для какого домена он создаёт, и прописывает эти данные в метаданных каждого созданного вопроса.

В случае наличия модификаций одного домена, которые оформлены в виде разных доменов, но используют одни и те же вопросы, вторичные домены переопределяют метод `Domain.getShortnameForQuestionSearch()`, где возвращают короткое имя базового домена, которым размечены все вопросы для этих доменов.
